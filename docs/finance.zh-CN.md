# Docker 日常账本

当前源码已实现日常账本，尚未发布新版本。订阅付款联动、自动化写入 API 与 Agent Skill 仍在后续阶段；Cloudflare 当前隐藏账本入口。实际实施状态见 [进度记录](plans/finance-progress.md)。

## 开始记账

1. 登录后进入“流水”，切换至“账户”，添加现金、银行等资金账户。账户币种固定，期初余额可为负，期初日期表示该余额生效的起点。
2. 点击“记一笔”，切换支出或收入，在图标网格选择分类，填写金额、账户及发生日期。发生日期不能早于账户期初日期。
3. 转账选择两个不同的同币种账户。转账改变两端余额，不增加收入或支出。
4. 在原消费上点击“退款”，填写实际退款金额和收款账户。可以多次部分退款，合计不能超过原消费。
5. 通过“编辑”更正流水，或填写原因后作废。存在有效退款时，应先处理退款，再作废原消费。归档账户保留历史余额及流水，停止新记账。

移动端账本页面提供固定的“记一笔”入口。账户页可以修改账本名称、基准币和 IANA 时区，例如 Asia/Shanghai。期初余额更正、账户归档及流水更正都有版本校验和变更记录；遇到其他页面已修改的冲突时，刷新后重新更正。

## 分类与图标

- 内置 32 个支出分类、10 个收入分类。支出覆盖三餐、零食、衣服、交通、旅行、孩子、宠物、话费网费、烟酒、学习、日用品、住房、美妆、医疗、发红包、汽车/加油、娱乐、请客送礼、电器数码、运动、水电煤、人情、洗衣、养生保健、饮料、购物、保险、税费、工作、订阅服务、还款及其它；收入包含工资、生活费、收红包、外快、股票基金、奖金、利息、租金、报销及其它。
- 支出和收入分别选择，支持搜索。点击“添加分类”，输入名称并从 40 种图标中选择；每账本最多 100 个自定义分类。分类与图标保存在当前用户账本，随备份恢复。
- 流水列表及分类支出统计显示对应图标；筛选器直接选择分类。既有文字分类保留，未匹配到图标的旧分类使用通用图标。内置分类以稳定标识保存，切换界面语言不改变分类事实。
- 退款继承原消费分类；商家和标签在记账表单“更多信息”中填写。自定义分类目前支持添加，不提供删除或重命名，避免改写既有分类事实。

## 看实际收支

“实际收支”按已入账流水统计，不计期初余额和转账；退款按实际发生日期冲减原消费分类。本月可以出现负的净支出，例如本月收到上月消费的退款。

不同币种分别展示，当前不生成跨币种总合计。日期范围最多 366 天。月度预算按指定币种的实际净支出计算，“实际收支”页面可设置账本基准币的整体月预算；分类预算也有产品 API。

既有“统计”页面仍展示订阅的周期折算和预计支出，既有订阅预算保持其原语义。推进订阅续费日期不会创建实际流水。

## 备份与恢复

- 账户页“导出账本”下载独立账本 JSON；选择文件后先查看恢复预览，再提交“恢复账本”。
- 原 Renewlet ZIP 数据导出及 Docker 云备份也包含 finance 段，可通过现有导入预览流程恢复。普通订阅 CSV 仍是订阅清单。
- 恢复只写入空账本；完整校验金额、余额、账户、退款关系和版本，再在一个事务中写入。来源 ID 会映射到当前用户的新 ID，不能授予其他用户的数据权限。
- 相同快照重复提交不会重复记账。旧文件没有 finance 段时保留当前账本。导入的历史审计标记为 import，区别于当前实例的操作。
- 用户快照上限为 500 账户、500 预算、10,000 流水、10,000 审计事件和 8 MiB JSON，超过限制明确失败。更大实例请备份完整 Docker data 目录及配置。
- 常规大量订阅导入仍按原有规则分块，整批不是一个原子事务；中途失败请保留原文件重试，查看逐批结果。账本快照本身以单个事务恢复。

升级已有 Docker 实例前先备份。启动时新增 collection 并为旧用户创建默认个人账本，迁移可安全重跑；不会从旧订阅日期推断已付款。不要把支付方式名称当作已创建的资金账户。

浏览器接口及领域约束见 [收敛契约](plans/finance-contract.md)。当前 `/api/app/finance` 使用网页登录与 CSRF，原 Public API Token 继续只读订阅，不能用它写账本。
